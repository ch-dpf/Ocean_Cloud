# Ocean_Cloud · 云海平台

React + TypeScript + Vite 应用级前端，使用 npm workspaces 管理主平台、业务应用和公共包。

开发入门见 [主平台与子平台开发教程](docs/platform-development-guide.md)，完整资料见 [文档目录](docs/README.md)。Java 上传发布的接入契约见 [后端接入说明](docs/java-backend-integration.md)。

## 启动

要求 Node.js 22.12+、npm 10+。应用管理需要独立的 Ocean_Cloud_Control 服务，两个项目放在同级目录。

先在 Ocean_Cloud_Control 执行：

```shell
npm ci
npm start
```

再在 Ocean_Cloud 执行：

```shell
npm ci
npm run dev
```

主平台：http://localhost:5173。后台服务：http://localhost:5180，仅监听本机。
主平台 Vite 会把 /api 和 /apps/ 代理到内部后台；主平台、地理信息和海洋信息共用 http://localhost:5173，仅访问路径不同。单独启动主平台：`npm run dev -w @ocean-cloud/portal`。
后台缺失时显示连接错误，不使用静态应用列表冒充已发布状态。

## 应用管理

- 创建：填写名称、唯一标识、/apps/xxx 路由、图标、描述和启用/展示状态，后台生成独立工程及本地 Git 仓库。
- 开发：在应用详情中查看工程位置。原地理信息、海洋信息仍在本仓库 apps 下，新增工程位于后台数据目录 projects 下。
- 发布：复制当前源码快照，执行依赖安装、TypeScript 检查和 Vite 构建；保存产物后切换当前版本。
- 回滚：选择历史发布版本，切换入口映射。构建失败不替换当前版本。
- 删除：应用移入回收站，列表移除且原入口返回 404；保留源码、发布版本、任务记录及标识和路由。存在执行中的任务时不可删除。可在回收站恢复原配置和版本。
- 路由：卡片读取后台配置，在当前标签页进入独立站点。返回平台同样使用当前标签页。停用后直接访问也会被后台拒绝；隐藏只影响应用中心展示。
- 初次启动的地理信息和海洋信息处于待发布状态，需要在应用管理中分别发布。

发布产物通过统一入口 /apps/xxx/ 提供，平台注入当前入口路径和返回地址。资源使用相对路径，修改入口路由无需重建。子应用内部仍使用 Hash 路由，未知页面显示 404，缺失静态资源返回真实 404。

## 配置与边界

主平台 VITE_API_BASE_URL 默认 /api；后端地址统一在根目录 backend.config.ts 声明，各应用的 Vite 代理都引用它，换后端只改这一处。需要临时改指向时可用进程环境变量 OCEAN_CONTROL_TARGET（主平台代理）与 OCEAN_BUSINESS_TARGET（业务接口代理）覆盖，本机 Node 控制服务为 http://127.0.0.1:5180。
子应用独立开发时，VITE_PORTAL_ORIGIN 默认为 http://localhost:5173，VITE_API_BASE_URL 默认为 /api。
VITE_* 为构建时配置，不能保存密钥。生产静态服务需配置管理接口代理与各应用站点路由。

目前为单机可信开发环境：已提供创建、发布、回滚和持久化配置；尚未实现统一认证/RBAC、远程 Git 拉取、容器隔离、远程服务器部署和多实例任务调度。
后台管理 API 与业务 API 不应混用；真实业务后端需要另行配置。不能将当前无登录的本地管理服务直接公开到网络。
详见同级 Ocean_Cloud_Control/README.md。

正式静态运行也可由后台统一托管主平台 apps/portal/dist 和所有子应用：先构建主平台，再把 PORTAL_ORIGIN 配置为实际统一入口并启动后台。此时所有页面、管理 API 和子应用都在同一个地址下。开发用的子应用独立端口不作为应用中心入口。

## 矢量样式制图

入口：地理信息 → 数据管理 → 矢量数据集 → 制图工作区。选中图层后点击“管理样式方案”。

- 进入工作区时读取每个图层的默认方案；支持新建、编辑、另存为、删除非默认方案和切换默认方案。
- 渲染规则按顺序取首个匹配项，支持上移、下移、点/线/面、属性条件与起止层级。起始层级包含边界，结束层级不包含边界；未命中或命中隐藏规则时不显示。
- 点可调半径、颜色、透明度与描边；线可调颜色、宽度与透明度；面可调填充、描边及各自透明度。尺寸单位为像素。
- 属性条件提供单条件编辑，组合或包含条件使用条件 JSON，支持 and、or、in 及其他后端协议运算符。字段按原名匹配，不自动转换文本与数字。
- 编辑抽屉打开时仍可操作地图；草稿实时预览，关闭后恢复默认方案。未保存修改在关闭、重新加载或切换方案时会提示放弃确认。
- 选中要素后可查看本地匹配结果；编辑面板可调用后端检查已保存方案在当前层级的匹配结果。保存前不会把草稿冒充已保存方案。

同一 GeoJSON 的点、线、面保留 SINGLE 数据图层。GeometryCollection 逐子几何应用规则，选取、属性与后端匹配仍使用原始要素 ID。

接口统一经 vectorService 与应用 httpClient 调用，地址为 /api/gis/vector/layers/{layerId} 下的 styles、default-style、styles/{styleId}/default 和 styles/{styleId}/match。创建、更新、默认切换读取真实 ETag；写操作使用 If-Match。412 保留草稿，可另存或重新加载，不自动重试覆盖。

前后端应部署同一版样式协议（schemaVersion=1），代理需保留 ETag，跨域时后端需暴露该响应头。OpenLayers 的实际连续缩放层级用于规则匹配；当前地图可交互层级为 Z0–Z22。样式修改不重新导入要素，也不更改要素数据版本。

## 矢量瓦片浏览与原始要素编辑

制图工作区使用动态 MVT 浏览，取消了视窗前2000个要素的截断。进入工作区后先读取图层和默认方案，汇总全部规则引用的字段与符号缓冲，再调用 `POST /api/gis/vector/layers/{layerId}/render-contexts`。地图按256像素XYZ瓦片请求 `GET .../tiles/{z}/{x}/{y}.mvt?contextId=...`，由统一 httpClient 接收 ArrayBuffer，OpenLayers 使用轻量 RenderFeature。最多4个渲染任务并由独立HTTP队列控制真实请求；切换上下文、离开视窗和卸载时取消等待与订阅，返回原视窗会恢复取消的瓦片。

点默认网格聚合，工具栏“点聚合”可切换为逐点显示。聚合按网格与全部规则字段的属性投影分组，确保属性与连续层级条件仍正确；不同类别可能产生多个重叠标记。点击聚合打开成员面板，使用 `GET .../clusters/{clusterId}/features?contextId=...&limit=50&cursor=...` 逐页加载原始要素，可选择成员或放大。计数为点位数，同时显示不同原始要素数。工具栏只显示实际加载的图层及瓦片状态，不把跨瓦片的几何片段累加为要素总数。

点击普通要素或聚合成员后，调用 `GET .../features/{featureId}` 获取完整 GeoJSON 和 ETag；选中及编辑使用独立覆盖层。属性及几何可在“编辑原始要素”中修改，地图支持拖动顶点。XYZ顶点拖动保留Z，插入新顶点需在几何JSON中明确填写高程；属性保存为完整替换。无效JSON或几何结构不会进入地图。保存和删除使用 If-Match，成功后刷新图层dataVersion和上下文，412保留草稿并提示重新加载后编辑。ID始终作为字符串传递。

颜色、透明度、规则值及层级变化本地重绘；字段清单、符号缓冲、聚合开关或数据版本变化才更新显示上下文。409自动刷新目录及上下文，410重建过期上下文，422提示区域过密并建议放大或启用聚合，其他失败提供重试。没有回退到有截断的GeoJSON地图加载路径。线按显示分辨率简化，面共用瓦片量化网格，原始几何不改变。

前后端需同时部署这组接口。后端依赖PostGIS与Redis，默认瓦片2MiB、SQL超时10秒，资源预算在后端 `gis.vector.tiles` 中配置；极区显示限于Web Mercator范围，复杂线面过密时仍可能需要进一步概化。代理需保留MVT二进制内容、HTTP状态及ETag，跨域部署暴露ETag。原始要素分页查询继续供精确查询及属性列表使用。

矢量瓦片的HTTP调度独立于OpenLayers渲染任务：整个地理信息应用最多2个真实在途请求，相同瓦片合并订阅。取消未发请求直接出队；已经发出的HTTP仍等到真实响应后才释放槽位，取消的订阅不再更新地图，避免浏览器中断后同步JDBC仍执行、补发又持续占满后端。瓦片请求使用 `retry:false` 关闭通用GET自动重试，其他读接口保持原策略，HTTP超时为35秒。

前端依据图层范围及当前样式层级过滤请求。给道路、建筑配置合理最小显示层级后，在隐藏层级不再请求明细瓦片；规则颜色或透明度变化仍仅重绘。后端每实例保留4个空间执行槽位、32个排队位置，最长排队10秒；同瓦片并发生成合并，等待不占用数据库连接，拿到槽位后重新校验版本再查询。队列、SQL及HTTP超时应一并配置。

动态切片需要匹配数据规模。真实道路Z7抽样瓦片仍达到约11MB，因此会明确触发422；需要小比例尺完整概览时应进一步建设多尺度概化或预生成瓦片，不能靠反复重试、提高并发或扩大响应预算解决。
